# Deploying the demo to Vercel

The demo is one static site in one Vercel project, `solid-mortgage`, at
<https://solid-mortgage.vercel.app/>. Every organisation app is served under its own path
(`https://solid-mortgage.vercel.app/<slug>/`, slugs in `content/orgs.ts`), and `/` redirects to
the front door, `/welcome/`. There is no application server: the pods run in the visitor's
browser (decision [0017](../decisions/0017-static-rebuild.md), `docs/rebuild/design.md` §d.8).

## Projects

| Vercel project | Source | URL |
|---|---|---|
| `solid-mortgage` | repository root (`vercel.json`) | https://solid-mortgage.vercel.app/ |
| `solid-mortgage-vocab` | `apps/vocab` (Next.js, its own project) | https://solid-mortgage-vocab.vercel.app/mort |

The vocab project hosts the permanent `mort` namespace
(`https://solid-mortgage-vocab.vercel.app/mort#`): keep it publicly dereferenceable and do not
move it.

The earlier per-app projects (`solid-mortgage-<app>.vercel.app`) now redirect to the matching
path on the one site. Their code was removed on 19 Nov 2026 and is in the git history before
that commit.

## How a deploy runs

`vercel.json` is generated by `tools/site-routes.mjs` (`node tools/site-routes.mjs --write`;
`--check` and a test fail on drift). It sets:

- `installCommand` `pnpm install --frozen-lockfile`, `buildCommand` `pnpm run build`,
  `outputDirectory` `dist`. `pnpm run build` (`tools/build-site.mjs`) builds every app and
  assembles `dist/<slug>/`, `dist/pods-sw.js`, `dist/agents/` and `dist/video/`.
- A single-page fallback per slug, `noindex` headers on every response, a year's caching for
  hashed assets, and cross-origin isolation only on `/wallet/prove` and `/wallet/lending/prove`.
- `ignoreCommand` `node tools/vercel-ignore.mjs`: production (merges to `main`) always builds; a
  preview builds only for a pull request labelled `preview` or a `preview/…` branch, which
  keeps the project under Hobby's daily deployment limit.

To check a build locally before it ships: `pnpm run build`, then `pnpm run preview` serves
`dist/` with the same routing rules, and `pnpm run test:e2e:site` runs the acceptance suite
against it.

## Environment variables

The site needs none. The optional feedback interviewer (`api/feedback/*`, `apps/feedback`) is
switched on by project environment variables listed in
[`packages/feedback/README.md`](../packages/feedback/README.md); set a spend limit first, as
that README says.
